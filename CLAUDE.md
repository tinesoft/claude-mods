# claude-mods

One Nx workspace and one plugin marketplace (`tinesoft-mods`). Each mod lives in `mods/<name>/` and is an Nx project.

`craftory` is an SDLC framework, built on top of Matt Pocock's skills, as a mod.

## Branches and commits

- Branch from `develop` as `feat/...`, `fix/...` or `chore/...`. PRs target `develop`. `main` is release-only.
- Conventional Commits, with the scope a project name (`session-activity`) or one of `repo`, `ci`, `deps`, `release`. commitlint rejects anything else.
- Never edit versions or `CHANGELOG.md` by hand. `nx release` owns `package.json` versions and `tools/sync-plugin-version.mjs` copies them into `.claude-plugin/plugin.json`.

## Mod code

- Claude Code loads `.ts` directly. There is no build.
- The rules for writing mod code are in CONTRIBUTING.md's "Writing mod code". ESLint enforces the mechanical ones, and `/code-review` checks the rest.
- `h` and `Fragment` are globals for JSX. Types come from the virtual module `claude-code`, declared in `tools/claude-code-types/<version>/index.d.ts`, a copy of the `.claude-plugin/types/` that Claude Code generates for the pinned version. Never edit the snapshot. To move versions, add a new snapshot and change the version everywhere it is pinned (see CONTRIBUTING.md).
- `.claude-plugin/types/` is generated by Claude Code and git-ignored. Do not commit it.
- Fitting a mod to VS Code: read `docs/agents/vscode-surface.md` before guessing at a layout or colour.

## Checks

Run before pushing:

```sh
pnpm nx affected -t lint typecheck validate test --output-style=static
node tools/sync-plugin-version.mjs --check
node tools/check-scratch.mjs
```

The `test` and `validate` targets run the Claude Code version CI pins (`CLAUDE_CODE_VERSION` in `.github/workflows/ci.yml`) through `tools/claude-pinned.mjs`, whatever the local `claude` is.

CI runs the same, plus `claude plugin validate . --strict` at the root, pinned to Claude Code 2.1.302.

## Agent skills

### Issue tracker

Local markdown under `.scratch/<feature-slug>/`. See `docs/agents/issue-tracker.md`. For what's open, run `node tools/scratch-status.mjs` (it reads through Craftory's Local reader), not a grep: `Status:` lines come plain or bold.

### Triage labels

Default five roles (`needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`), recorded as a `**Status:** <role>` line in the issue file. See `docs/agents/triage-labels.md`.

### Domain docs

Multi-context: `GLOSSARY-MAP.md` points to `mods/craftory/GLOSSARY.md` and `mods/session-activity/GLOSSARY.md`; ADRs per mod plus repo-wide. See `docs/agents/domain.md`.
