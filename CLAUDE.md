# claude-mods

One Nx workspace and one plugin marketplace (`tinesoft-mods`). Each mod lives in `mods/<name>/` and is an Nx project.

## Branches and commits

- Branch from `develop` as `feat/...`, `fix/...` or `chore/...`. PRs target `develop`. `main` is release-only.
- Conventional Commits, with the scope a project name (`session-activity`) or one of `repo`, `ci`, `deps`, `release`. commitlint rejects anything else.
- Never edit versions or `CHANGELOG.md` by hand. `nx release` owns `package.json` versions and `tools/sync-plugin-version.mjs` copies them into `.claude-plugin/plugin.json`.

## Mod code

- Claude Code loads `.ts` directly. There is no build.
- Never alias `$`. Hooks receive `($, e, next)`; name them exactly that.
- Helpers in `src/` take plain data, never `$`, so `claude plugin test` can test them without the engine.
- Every hook calls `next(e)` and returns its result unless it deliberately answers for itself.
- `h` and `Fragment` are globals for JSX. Types come from the virtual module `claude-code`, declared in `tools/claude-code-types/<version>/index.d.ts`, a copy of the `.claude-plugin/types/` that Claude Code generates for the pinned version. Never edit the snapshot. To move versions, add a new snapshot and change the version everywhere it is pinned (see CONTRIBUTING.md).
- `.claude-plugin/types/` is generated by Claude Code and git-ignored. Do not commit it.

## Checks

Run before pushing:

```sh
pnpm nx affected -t lint typecheck validate test
node tools/sync-plugin-version.mjs --check
```

Run tests on the pinned Claude Code (`CLAUDE_CODE_VERSION` in `.github/workflows/ci.yml`). A local `claude` auto-updates and can disagree with CI.

CI runs the same, plus `claude plugin validate . --strict` at the root, pinned to Claude Code 2.1.302.
